# Suraksha DHPMS — Execution Plan

Source material: `HUMBRIX - DHPMS( Draft ).pdf` (original product sketch) and
`Hospital_Health_Card_System_Requirements.docx` (enterprise blueprint — PRD, app
flow, tech stack, design system, DDL schema, implementation roadmap). No `./docs/`
folder exists in this repo; both files live at the project root and are treated as
the authoritative spec. This plan restructures the blueprint's 6-phase roadmap into
the 6 phases requested, with the exact schema/stack/palette from the source docs.

## Tech Stack (from blueprint Document 3)

**Backend:** Python 3.12+, FastAPI, Pydantic v2, SQLAlchemy 2.0 (async), asyncpg,
Alembic, PostgreSQL 16, Redis 7, Celery, JWT + Argon2id, python-jose, qrcode[pil],
reportlab (PDF cards/prescriptions).

**Frontend:** Next.js 15 (React 19, App Router), Tailwind CSS, Shadcn UI, TanStack
Query v5, Zustand, html5-qrcode, Zod, react-hook-form, axios.

**Infra:** Docker Compose (Postgres 16 + Redis 7 services) — no local `psql` client
present, so Postgres runs containerized for both dev and Alembic autogeneration.

---

## Phase 1 — Core Infrastructure & PostgreSQL Database

**Goal:** FastAPI skeleton + async SQLAlchemy models for the full schema.

- `docker-compose.yml`: `postgres:16`, `redis:7` services.
- `backend/` — DDD layout:
  - `app/core/config.py` (Pydantic settings), `app/core/database.py` (async engine/session), `app/core/security.py` (JWT/Argon2id, added when auth is implemented in a later phase)
  - `app/models/` — SQLAlchemy 2.0 async ORM, one module per aggregate, mapping the 13-table DDL 1:1: `users`, `membership_plans`, `patients`, `qr_cards`, `departments`, `doctors`, `appointments`, `visits`, `prescriptions`, `prescription_items`, `invoices`, `invoice_items`, `audit_logs`, plus all Postgres ENUM types (`user_role`, `gender_type`, `appointment_status`, `card_status`, `membership_tier`, `invoice_status`).
  - `app/schemas/` — Pydantic v2 (added alongside the API routers that need them, from Phase 3 onward)
  - `alembic/` — initial autogenerated migration against the dockerized Postgres instance
  - `requirements.txt`, `Dockerfile`
- **Testing:** `backend/tests/test_models.py` written *first* (red) — asserts every model imports, `Base.metadata` contains all 13 tables, and (integration test) `Base.metadata.create_all` succeeds against the live dockerized Postgres, and a row can be inserted/queried for the `users` and `patients` tables. Implementation follows to turn it green.

## Phase 2 — Frontend Scaffold

**Goal:** Next.js 15 shell with the clinical design system and portal routing skeleton.

- `frontend/` via `create-next-app` (TypeScript, App Router, Tailwind, `src/` dir, ESLint).
- Shadcn UI initialized; base primitives added as needed.
- `src/app/globals.css` — clinical palette as CSS variables (Deep Cyan `#0284C7`, Medical Slate `#0F172A`, Emerald `#10B981`, Red `#EF4444`, Amber `#F59E0B`).
- Route shells (Server Components, no data yet):
  - `src/app/(staff)/reception/scanner/page.tsx`
  - `src/app/(staff)/doctor/dashboard/page.tsx`
- **Testing:** Vitest + Testing Library configured; a failing smoke test written first for each shell page (renders expected heading/role), then the page implemented to pass. `npx vitest run` as the build check.

## Phase 3 — Patient Registration & Cryptographic QR Token Generation ✅ *(done)*

- `app/api/v1/patients.py`, `app/api/v1/qrcards.py`, `app/api/v1/memberships.py`, `app/services/patient_id_service.py`, `app/services/qr_service.py`, `app/services/pdf_card_service.py`.
- Universal Patient ID generator (`SUR-YYYY-NNNNNN`), non-guessable UUIDv4 token issuance into `qr_cards`, CR80 print-ready PDF card generation (ISO/IEC 7810 ID-1, via `reportlab` + `qrcode`).
- Frontend: `/register` page, `src/components/cards/PatientHealthCard.tsx`.
- Verified live end-to-end through the browser (real patient `SUR-2026-000001` registered, card PDF downloaded).

## Phase 4 — Auth, Front-Desk Scanner & Queue Routing ✅ *(done)*

- `app/core/security.py` (Argon2id + JWT), `app/api/deps.py` (current-user dependencies), `app/api/v1/auth.py` (login).
- `GET /api/v1/scan/{token_uuid}` — role-aware resolver (staff dossier vs. public emergency view) per blueprint Prompt A.
- `app/services/queue_service.py` + `POST /api/v1/appointments/queue` — OPD queue token issuance (`DEPT-NNN` format, e.g. `CARDIO-001`), staff-role gated.
- Frontend: `src/components/qr/QrReaderModal.tsx` (html5-qrcode, camera-denied fallback to manual token entry) per blueprint Prompt B.

## Phase 5 — Clinical Suite ✅ *(done)*

- `app/api/v1/consultations.py` — vitals capture, chief complaint/symptoms, diagnosis, doctor's notes → `visits`; e-prescription builder → `prescriptions` / `prescription_items`; patient history lookup; doctor-role gated throughout.
- `app/services/prescription_pdf_service.py` — prescription PDF export with letterhead.
- Frontend: `src/components/clinical/VitalsForm.tsx` (BP/HR/temp/SpO2/weight/height with live BMI calculation and blueprint validation rules).

## Phase 6 — Tiered Memberships & Automated Discount Billing ✅ *(done)*

- `app/services/discount_engine.py` — `calculate_invoice_breakdown()` per blueprint Prompt C, applying tier-specific % off per cost center (Consultation / Lab / Pharmacy) into `invoices` / `invoice_items`. Pytest-verified across FREE/SILVER/GOLD/PLATINUM.
- `app/api/v1/billing.py` — invoice creation (staff-gated) and lookup.
- Frontend: `src/components/billing/BillingSummary.tsx` — gross/discount/net breakdown display.
